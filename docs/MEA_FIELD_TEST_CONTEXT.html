01 · Purpose

This document is a self-contained engineering brief for any human or agent that must build a local testing environment and improve Kilosort for Litke multi-electrode array (MEA) recordings. It encodes machine limits, data layout, conversion semantics, production parameters, native upstream tests, and recommended work tracks for accuracy, speed, and memory.

Primary product under development: the fork branch mea-optimizations of Kilosort (Python / PyTorch), used by the Manookin lab MEA pipeline (MEA-fieldlab). Production sorts historically run on a GPU workstation; this host (fieldlab) is for development, micro-benchmarks, and CPU regression— not full-length chunk sorts.

Design intent for agents
Prefer small, reproducible fixtures; preserve bit-exactness where the branch claims it; never assume Neuropixels defaults for Litke data; never assume a CUDA device is present on fieldlab.

04 · Data pipeline (Litke → Kilosort)

Litke raw data is not Neuropixels AP binary. It arrives as large (~1.8 GB) per-file Litke bins that must be joined, channel-selected, transposed, and written as int16 time-major binaries that Kilosort understands.

Raw Litke bins → prepare_data.sh → convert_join… -b → chunkN.bin → run_kilosort4.py → sorted/…/kilosort4/

Orchestration

  • MEA-fieldlab/src/utilities/pipeline.sh — full experiment/chunk orchestration (spacing, CAR, sort, process spikes, dedup).
  • prepare_data.sh — builds file list, calls converter with -b.
  • convert_join_litke_datasets_for_yass.py — actual binary rewrite (also used historically for YASS).
  • run_kilosort4.py — builds settings + probe, calls kilosort.run_kilosort.
  • Alternate converters: convert_litke_to_yass.py, litke_to_binary.sh.

Conversion semantics (critical for fixtures)

In convert_join_litke_datasets_for_yass.py, the reader uses bin2py.PyBinFileReader(..., is_row_major=True). Samples on connected channels are written as: 

samples_to_write = np.ascontiguousarray(
    samples_connected_channels.T.astype(np.int16)
)
samples_to_write.tofile(yass_binfile_output)

Interpretation for agents: transpose then flatten to little-endian int16, yielding a Kilosort-style (ntime, nchan) memory order in the file. Do not invent a new layout for tests; reuse this converter or match it exactly.

pipeline.sh → kilosort invocation

# When ALG is 4 (conceptual excerpt):
python run_kilosort4.py ${EXP} ${CHUNK} -e ${ARRAY_SPACING} [-c for CAR]

Binary expected at ${TMP_PATH}${CHUNK}.bin (under sorted experiment folder). On fieldlab, for 20251204A, the large intermediate chunk1.bin was not present at survey—only kilosort result directories and raw Litke bins.

07 · Probes, spacing, geometry

  • 20251204A is 30 µm spacing (log: dmin/dminx = 30, 519 channels, 30UM probe). Confirm with ops/log for any other experiment before assuming 60.
  • Operator belief: remaining common datasets use 60 µm unless otherwise labeled. Validate per run via ops.npy or log.
  • Channel positions for completed sorts are available as channel_positions.npy and channel_map.npy in each kilosort4 folder—prefer these for post-hoc geometry over re-deriving from mats when comparing results.
  • Hex-like dense arrays: nearest_chans=19 corresponds to two rings of neighbors in lab comments.
Accuracy note
Wrong pitch or probe mat silently degrades clustering (template spacing, whitening neighborhoods, center placement). Any MEA fixture must ship with the matching .mat and the same dmin/n_chan_bin.

Accuracy criteria used by the branch language: bit-exact where claimed (spike times, compiled body), else numerical / count tolerances. For MEA golden comparison against lab GPU outputs, start with:

  • Spike times and cluster IDs (after any keep-mask)
  • Number of units and spikes within agreed bounds
  • Optional: templates / whitening matrices if intermediate pins are needed

10 · Recommended test strategy on fieldlab

Track A — Upstream regression (always first)

  • Editable install of mea-optimizations into conda env kilosort.
  • Run fast pytest; optionally --runslow on NP mini bin already cached.
  • Goal: catch generic breakages; CPU only.

Track B — MEA micro-benchmarks (primary local work)

  • Build a fixture binary: 1–5 batches or 10–60 s from Litke raw via the official converter.
  • Pair with correct probe mat and settings dict cloned from production (table in §06).
  • Benchmark only modified functions when possible (unit-level tensors) for speed/memory.
  • For bit-exact claims: fixed seeds / deterministic wTEMP paths; compare arrays with equality.

Track C — Short end-to-end smoke

  • 60 s MEA bin ≈ 1.25 GB; feasible on disk; CPU wall time may be long—use reduced peels for iterative speed work, but keep a “production-params” golden job separate.
  • Store outputs under a dedicated results dir; do not overwrite lab goldens in sorted/.

Track D — Full parity (off-box)

  • Requires GPU workstation (e.g. prior RTX 4000 Ada machine). Use for final acceptance of speedups and for regenerating goldens.
  • fieldlab cannot substitute.

Memory discipline on 15 GiB

  • Avoid loading entire multi-GB bins into RAM; stream as KS does.
  • Prefetch buffers add peak memory—measure RSS when testing I/O changes.
  • Prefer float32 batch views already used by KS; do not introduce full-float64 copies.
  • Close concurrent heavy processes; leave headroom for OS cache of sequential reads.

Capacity formulas (CPU RAM discipline)

get_spike_buffer_capacity(n_batches) =
    min(1e6, max(1e4, 1e4 * n_batches))

get_clip_buffer_capacity(n_batches, nskip=25) =
    n_used = max(1, ceil(n_batches / nskip))
    min(5e5, max(1e4, n_used * 5e3))

# extract_wPCA_wTEMP (after skeptic fix):
#   start at get_clip_buffer_capacity(...)
#   grow: double until need met or CLIP_BUFFER_HARD_CAP (500_000)
#   at hard cap: partial-fill remaining room, then stop
#   if zero clips after all batches: RuntimeError (never silent SVD fail)

Short fieldlab fixtures therefore allocate ~10k–20k clips initially instead of a fixed 500k×nt float32 slab (~122 MiB at nt=61), but still absorb a dense first batch.
